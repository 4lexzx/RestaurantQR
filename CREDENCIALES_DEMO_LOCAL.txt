MENUGO - CREDENCIALES DE PRUEBA LOCAL
====================================

MenuGo atiende UN SOLO restaurante. No hay tenants, ni panel SuperAdmin,
 ni selector de restaurante: todas las cuentas son del mismo local.

Estas cuentas son exclusivamente para desarrollo y testing local.
Cambiar o eliminar todas las contraseñas antes de publicar el sistema en producción.
Este archivo no contiene credenciales de PostgreSQL, tokens ni secretos del servidor.

Servidor local: http://localhost:4000

1. Cliente (QR / para llevar) — sin login
------------------------------------------
Carta por mesa:      http://localhost:4000/Cliente/menu.html?mesa=1
Para llevar:         http://localhost:4000/Cliente/para_llevar.html
Entrada con mesa:    http://localhost:4000/Cliente/mesa/1
(Los QR se generan y listan en el panel Mesero con GET /api/mesas/qr-urls,
 que devuelve numero_mesa, qr_token, qr_activo y url_qr ya listos para imprimir.
 Mesa 1 de ejemplo:
   qr_token = MG-MESA-01-9F5BA8CB417B
   url_qr   = http://localhost:4000/Cliente/mesa/1?token=MG-MESA-01-9F5BA8CB417B)

Notas
-----
- El Admin accede con los campos `usuario` y `clave` (endpoint POST /api/auth/login).
  Mesero y Cocina usan `usuario`, `clave` y `rol` (POST /api/admin/personal/login).
- Las rutas /r/menugo/... se mantienen solo como alias de compatibilidad.
  No usarás esos enlaces: entra siempre por http://localhost:4000/<Panel>/...
- Para regenerar los QR: el backend los crea y conserva solo al arrancar
  (backend/src/config/qrMesas.js, formato MG-MESA-<n>-<hex>) y cada vez que se
  cambia num_mesas en Configuracion. Son idempotentes: si qr_token ya existe se
  respeta. Para forzar uno nuevo: UPDATE mesas SET qr_token = NULL WHERE
  numero_mesa = <n>; y reiniciar el servidor. No se editan a mano.
